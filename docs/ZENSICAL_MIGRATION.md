# Zensical Migration Notes

This branch ports the documentation site from MkDocs + Material for MkDocs to
[Zensical](https://zensical.org/) 0.1.0. This file is not part of the
published site (`exclude_docs` in `zensical.toml`).

## Summary

- `just docs` runs `docs/scripts/gen_docs.py` (generated pages), then
  `zensical build --strict`. The full site builds with no warnings, including
  Zensical's built-in internal link and anchor validation.
- The page set matches the MkDocs build: 2360 HTML pages vs 2361; the only
  difference is the `navigation/` page, a rendering of the literate-nav file
  that is now excluded.
- The Test Case Reference (2250 generated pages), the `fill --help` page and
  the CONTRIBUTING/SECURITY copies are generated by a pre-build script.
- mkdocstrings works (Zensical integrates it), so no page loses API docs.
- Dropped: git-authors (page "Contributors" footer) and the vestigial mike
  version provider. The MkDocs hook was ported to JavaScript.
- Docs dependency group: 18 direct dependencies before, 4 after; 59
  packages in the group's resolved closure before, 27 after.

## Generated Pages (gen-files Replacement)

`docs/scripts/gen_docs.py` (`just docs-gen`, run by all `just docs*` recipes):

- Copies CONTRIBUTING.md/SECURITY.md to `docs/getting_started/` (with the
  existing link fix-ups).
- Writes `fill --help` to `docs/filling_tests/filling_tests_command_line_options.md`.
- Runs `fill` in-process with the `gen_test_doc` and `eip_checklist` plugins.
  `gen_test_doc` no longer imports `mkdocs_gen_files`: it writes files below
  `--gen-docs-output-dir` (default `docs`) through a small file writer that
  implements the existing `FileOpener` protocol, and builds the literate-nav
  list itself (a ~20 line port of `mkdocs_gen_files.Nav.build_literate_nav`)
  into `docs/tests/navigation.md`.
- Fails if any warning is logged by the generators (the old flow relied on
  `mkdocs build --strict` for this).
- `--fast` / `FAST_DOCS=true` generates `tests/frontier` plus the test modules
  linked from hand-written pages, so the strict build passes in fast mode too
  (with MkDocs, `just docs-fast` failed strict mode with 6 "not found" link
  warnings).

Generated paths are gitignored and excluded from markdownlint's default globs
and from codespell.

Note: `gen_test_doc` treats `--strict` in `sys.argv` as a deploy build and
requires `GEN_TEST_DOC_VERSION` (the Justfile exports it as `local`). The
generator no longer runs inside `mkdocs build --strict`, so this check no
longer triggers; the variable is still exported.

`eest clean` now also removes `docs/tests`.

Checklist pages (`tests/**/checklist.md`) are now excluded from search: one
filled checklist is about 2 MB and exceeded Zensical's per-section search
index limit (148231 token positions; maximum 65536), which failed the build.

## Dependencies

Measured with `uv export --frozen --no-dev --no-hashes`:

| | MkDocs (`mkdocs` group) | Zensical (`docs` group) |
| --- | --- | --- |
| Direct dependencies in the group | 18 | 4 (`zensical`, `mkdocs-click`, `mkdocstrings`, `mkdocstrings-python`) |
| Packages in the group's closure (`--only-group`) | 59 | 27 (28 lines; pymdown-extensions is locked at two versions by Python marker) |
| Third-party packages for project + group (`--group <g> --no-emit-workspace`) | 77 | 49 |

Base project without any docs group: 23. Zensical alone resolves to 11
packages; mkdocstrings + mkdocstrings-python account for most of the rest
(mkdocs, mkdocs-autorefs, mkdocs-get-deps, ghp-import, mergedeep,
pyyaml-env-tag, watchdog, python-dateutil, six, griffelib, ...).

Removed from the docs group without replacement: `mike`, all `mkdocs-*`
plugins, `mkdocs-material(-extensions)`, `cairosvg` and `pillow` (social
cards), `codespell` (already in the `lint` group), `pyspelling` and `lxml`
(unused), `Jinja2` (a dependency of the testing package) and the
`markdown==3.8` pin (reason unknown, no problems seen without it).

## Build Times (Incidental)

Local machine, busy with other jobs, so treat these as rough:

| | MkDocs | Zensical |
| --- | --- | --- |
| Full (generation + build) | 4m49s (generation ~85s) | 4m48s (generation ~88s, build ~186s) |
| Fast mode | ~61s (then failed strict mode) | ~35s generation + ~39s build |
| Rebuild, unchanged sources (warm `.cache/`) | n/a | ~34s |

The Zensical build time is dominated by mkdocstrings rendering of ~2250 test
pages (run in Python); Zensical caches rendered pages in `.cache/`.

## Known Issues and Not Verified

- CI changes (`docs-build.yaml` site_url rewrite, path filters) were linted
  with actionlint but not run.
- The `site.js` replacement for the reference-new-tab hook was checked in
  headless Chrome only, not by clicking in a desktop browser.
- `zensical serve --strict` is unsupported (it prints a warning); `docs-serve`
  does not pass it.
- `zensical serve` does not regenerate the test case reference when tests
  change (MkDocs re-ran gen-files on reload); re-run `just docs-gen`.
- No `docs-mkdocs` fallback recipe: the MkDocs and Zensical toolchains need
  incompatible pymdown-extensions versions (mkdocs-material 9.x vs Zensical),
  so they can't share one lock file.
- The `gen_test_doc` and `eip_checklist` plugin loggers were renamed from
  `mkdocs` to `gen_docs`.
