# Vendored OpenRPC schema

`openrpc.json` is the JSON-RPC specification from
[`ethereum/execution-apis`](https://github.com/ethereum/execution-apis),
vendored here because upstream gitignores it — it is a build artifact of
`src/*.yaml`, produced by their Go `specgen` tool and therefore not
available from a clone or a release asset.

It is the authority for **response shapes**. Values come from the Python
spec via `ethereum-spec-evm`. See
`docs/plans/2026-08-08-spec-derived-rpc-tests-design.md`.

## Refreshing

```sh
just refresh-openrpc                  # current pin
just refresh-openrpc v1.0.0-beta.8    # bump the pin
```

The recipe clones execution-apis at the tag, builds `specgen`, and
regenerates this file with the same flags hive's `rpc-compat` simulator
uses, so the schema we validate against matches the one clients are
tested against upstream. It requires Go.

After bumping, update the pin table above and review the diff — a change
in a required field or a response shape may invalidate stored
expectations.

## Fork conditionality

The `eth_` namespace in this schema is **fork-agnostic**: one `Block`
schema serves every fork, so fork-dependent fields such as `blobGasUsed`
and `withdrawalsRoot` are marked optional. Schema validation therefore
cannot assert "required at Cancun".

This directory is the intended home for per-fork required-field overlays
that upstream cannot express. None exist yet.
