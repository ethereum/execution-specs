block_level_constraint = the BinaryTree fork is meant to enforce that the block header's `state_root` equals the tree-computed root -- rejecting a block whose header carries a wrong value rather than merely computing and reporting the correct one. tests/binary_tree/eip8297_partitioned_binary_tree/test_multi_block.py::test_block_with_wrong_state_root_is_rejected records this expectation by injecting a wrong `state_root` via `rlp_modifier`, but that is exactly the condition under which `fill` skips its own block-exception verification, so nothing checks the expectation at fill time, nor does any client, since none consumes BinaryTree fixtures; a `tests/binary_trie/` unit test is where a direct, checked guarantee belongs. This section's boundary/content/fork-transition sub-items are shaped for a numeric-threshold constraint (e.g. a size limit); a root-equality check has none of those axes, so this one test records the constraint's existence, not per-axis variation across boundary values, block content, or fork-transition timing
